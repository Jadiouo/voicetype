# 用自己的聲音做合成測試與增強

2026-09-22。這是下一階段的實驗設計；本次沒有克隆聲音、訓練模型或產生合成錄音。

## 判斷

可以用自己的聲音生成「有腳本的語音」，快速找出人名、中英切換、縮寫的失敗案例。先用它比較 ASR／熱詞／文字校正，等真實錄音證明有改善，再考慮訓練。現有文字修正學習與這個實驗分開：新增詞庫能立即改變輸出，跑一次 TTS→ASR 不會自行更新辨識模型權重。

合成語音可以改善 ASR，但效果取決於資料多樣性與真實／合成資料如何混合；不能由「聲音像我」推論「對我的實際說話一定有效」。2025 年的研究比較多種合成資料增強，指出直接混合不一定最好，部分變化在其實驗中無效。[Ogun et al., 2025](https://arxiv.org/abs/2503.08954)

早期 SynthASR 也使用獨立訓練的 TTS，混合真實及合成錄音訓練辨識模型，並調整抽樣權重。這支持把合成資料當補充，而不是用單一 TTS 聲音取代真實錄音。[Fazel et al., 2021](https://www.isca-archive.org/interspeech_2021/fazel21_interspeech.pdf)

## 第一個實驗

1. 從**你確認過**的修正中挑 10–20 個詞。用訓練／開發集的詞生成短句，每句包含一個目標詞；加入正常、否定、疑問，以及同音不同人的干擾情境。
2. 用一小段你本人錄製、逐字核對的參考音訊做零樣本聲音克隆。先不用訓練新的 TTS。參考錄音只能來自訓練區，不能拿保留驗收錄音當參考。
3. 保存腳本、實際生成的 WAV、TTS 型號／版本、參考錄音 ID、種子與生成設定。不要只保存 ASR 最後結果。
4. 聽過並確認**目標詞確實被念對**後，才把腳本當成該段音訊的標註。TTS 可能念錯多音字、人名、縮寫，或漏字；給它的文字只是預期內容，不保證等於音訊。另一個 ASR 可以篩查，但不能單獨當裁判。
5. 用相同音訊比較原版、詞庫版、上下文版。分開記錄目標詞正確率、整句 CER／英文 WER、正確內容被誤改的比例、等待時間。
6. 只有開發集改善時，才在事先保留的**真實麥克風錄音**驗收；不改善就保留原模型。合成測試結果單獨報告，不能與真人錄音合併成一個漂亮分數。

步驟 4 的標註要求與以下切分規則是本專案的實驗設計，並非上述論文對本機效果的保證。

## 防止自己出題、自己背答案

- 分成真實訓練集、真實開發集、真實保留驗收集；按錄音日期／會話切分，避免同一句的不同片段跨區。
- 克隆參考、合成腳本、詞庫修正與提示詞調整只看訓練／開發區。驗收腳本不拿去生成訓練音訊。
- 另外保留「新姓名／新專案」案例，分開衡量已記住的詞與未見過的詞。
- 模型跑錯時先辨別是 TTS 念錯、ASR 聽錯、上下文選錯，還是後處理改錯，不自動把所有失敗加入詞庫。
- 持續調參後，舊驗收集逐漸變成開發集；需要新的真人錄音做下一次驗收。

## 本機候選與資源

Qwen3-TTS-12Hz-0.6B-Base 的官方介面提供 `ref_audio`、`ref_text` 與 `generate_voice_clone`，可列為聲音克隆候選。官方範例使用 CUDA，因此不能由模型大小或文件中的延遲宣稱部署目標的 CPU／內顯跑得動、跑得快。[官方模型卡](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-0.6B-Base)

若執行這個實驗，先驗證 CPU／指定 AMD 內顯後端，測 1–3 句的實際耗時與記憶體。生成可以離線排程，不放進每次按鍵的語音輸入流程；維持不使用 NVIDIA 獨顯的設定。沒有相容後端就停止該候選，不默默改成 CUDA。

下一階段若需要 ASR 微調，還必須選定可訓練的模型實作與 CPU 可部署產物，定義訓練成本與退版方式。這不是刪除 SenseVoice 的日文標籤就能完成的事。
